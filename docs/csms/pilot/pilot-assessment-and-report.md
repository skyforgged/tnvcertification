## Part C — Pilot review: process findings and corrective actions

| ID | Process test | Result | Improvement / action before any real pilot |
|---|---|---|---|
| PILOT-OBS-01 | Criteria traceability | Demonstrated only with a fictional source | Add a mandatory source-verification record: publisher/owner, exact title, revision, issue/effective date, retrieval date, URL/controlled copy, applicability and superseded status. |
| PILOT-OBS-02 | Requirement-to-evidence mapping | Demonstrated | Add unique controlled IDs for source clauses and evidence; preserve source extracts/reference locations under document control. |
| PILOT-OBS-03 | Evidence sufficiency language | Mostly clear | Distinguish “record supplied” from “requirement demonstrated”; never infer implementation/effectiveness from document presence alone. |
| PILOT-OBS-04 | Sampling limitations | Captured at high level | Add sample rationale, population, selection method, period, exceptions and access restrictions to each real assessment record. |
| PILOT-OBS-05 | Competence authorization | Not demonstrated | Do not assign personnel until competence evidence is reviewed against the actual scope and formally authorized. |
| PILOT-OBS-06 | Impartiality | Not testable with fictional roles | Complete person-by-person and engagement-specific conflict screening; record safeguards and independent approval. Decline where threats cannot be acceptably controlled. |
| PILOT-OBS-07 | Technical review | Role separation described, not tested | Define reviewer competence, review depth, correction workflow and final report authorization. |
| PILOT-OBS-08 | Data protection and retention | Not tested | Approve channels, access roles, privacy notices/contract terms, retention periods and secure disposal before receiving real evidence. |
| PILOT-OBS-09 | Client factual review | Not tested | Add a controlled factual-correction stage that does not permit the client to suppress or rewrite substantiated findings. |
| PILOT-OBS-10 | Complaints and appeals | Not tested | Define complaint intake, independent handling, response timelines and records in the approved procedure. |

### Pilot exit decision

**Decision: Process prototype demonstrated; real-world pilot not yet authorized.**

The simulation shows that the current templates can produce a traceable mock matrix, assessment record and report. It does not validate assessor competence, impartiality in a real engagement, the accuracy of any principal criteria, legal sufficiency, data protection controls, or operational effectiveness. Close the actions above and obtain the outstanding governance approvals before considering a real customer pilot.
