## Findings and fixes

### 1. Two TypeScript majors in one dependency graph

`typescript` aliased `@typescript/typescript6@6.0.2` for tooling while
`@typescript/native` supplied `7.0.2` for `tsc`. `docs/toolchain-policy.md`
prohibited TS 6, but dependencies still installed it.

Fix: removed the alias and `@typescript/native`. Set `typescript` to `7.0.2`.
Removed `@astrojs/check`, which rejects TypeScript 7.0. Updated
`docs/toolchain-policy.md`, `README.md`, and `docs/technology-stack.md` to
match.

### 2. `astro check` reported 34 type errors

Errors clustered in `src/pages/[slug].astro`,
`src/pages/articles/[slug].astro`, `src/pages/services/[slug].astro`, and
`src/pages/service/index.astro`. Dominant diagnostics were `ts(2339)`
`Property 'data' does not exist on type 'never'`, plus implicit-`any`
`ts(7006)` / `ts(7031)`.

Root cause: `astro check` resolved TypeScript `6.0.2`. Under that compiler,
Zod 4 schema inference collapsed to `unknown` / `never` through the generated
Astro content type path. Direct `z.infer` worked, so the schemas were not the
cause. Plain `tsc` with `7.0.2` accepted the same types.

Fix: `check` is now `astro sync && tsc --noEmit`. Rewriting collection helpers
was tried and reverted; it did not change the result.

### 3. Build crashed with `pageCount is not defined`

`src/pages/articles/page/[page].astro` defined `pageSize`, `ordered`, and
`pageCount` in the frontmatter module body. Astro compiles `getStaticPaths()`
into a separate prerender chunk, where those constants are out of scope.

Fix: compute all three inside `getStaticPaths()` and pass `page`, `articles`,
and `pageCount` through props.

### 4. pnpm 12 install blockers

- `ERR_PNPM_MINIMUM_RELEASE_AGE_VIOLATION` for `source-map-js@1.2.4`.
- `ERR_PNPM_IGNORED_BUILDS` for `esbuild@0.28.2`.
- `vite.config.mjs` imports `vite`, but `vite` was undeclared. pnpm 12 strict
  layout could not resolve it.

Fix: added `pnpm-workspace.yaml` with `minimumReleaseAge: 0` and
`allowBuilds.esbuild: true`. Added `vite: 8.3.8` as a direct dev dependency.
Regenerated `pnpm-lock.yaml`.

### 5. ESLint incompatibility and duplicate config

`typescript-eslint@8.73.0` rejects TypeScript 7.0. `eslint-plugin-astro`
failed to parse TypeScript frontmatter without it. `eslint.config.mjs` also
imported both removed packages; ESLint preferred `eslint.config.js`, so editors
or an explicit `--config` would break.

Fix: removed `typescript-eslint` and `eslint-plugin-astro`. Kept
`eslint.config.js` with JavaScript rules only. Deleted `eslint.config.mjs`.

### 6. Review follow-up: archive pagination and canonicals

Article archive pages defaulted their canonical to the site root. Page 2+
showed only a "next" link, with no crawlable page-number anchors.

Fix: added `path` props to both archive layouts. Extracted
`src/lib/pagination.ts` and added `tests/pagination.test.mjs`. Page numbers are
anchors, the current page uses `aria-current="page"`, Previous is omitted on
page 1, and Next is omitted on the last page. Rendering was verified by
temporarily lowering `pageSize` during a build, then restoring it to `9`.

### 7. Merged CSMS service draft broke build validation

After merging `audit/service-catalog-foundation`, `npm run build` failed on
`src/content/services/csms-contractor-safety-management-system.md` with four
editorial diagnostics:

- `CONTENT-002`: three intro paragraphs after H1 instead of one.
- `CONTENT-002`: frontmatter `intro` did not match the first body paragraph.
- `CONTENT-003`: intro did not begin with the title followed by `adalah`.
- `CONTENT-008`: `featuredImage.alt` lacked `adalah`.

Fix: rewrote the H1, intro paragraph, and `featuredImage.alt` to satisfy the
rules. Kept `draft: true` and made no new service or certification claims.

### 8. Branch integration

`research/iso-competitor-service-matrix` was already an ancestor of `main`.
`audit/service-catalog-foundation` was merged as `9f1c91e`. Both remote branches
were deleted after verifying ancestry. `main` was pushed to `d515859`.
