## Problem 1 — `astro check` fails with 34 type errors

Error distribution:

- `src/pages/[slug].astro`: 11 errors
- `src/pages/articles/[slug].astro`: 11 errors
- `src/pages/services/[slug].astro`: 10 errors
- `src/pages/service/index.astro`: 2 errors

Dominant diagnostics:

- `ts(2339)`: `Property 'data' does not exist on type 'never'.`
- `ts(7006)`: implicit `any` on `entry` / `service` callback parameters
- `ts(7031)`: implicit `any` on destructured `{ data }` parameters

Root cause:

- `.astro/content.d.ts` derives entry data from
  `ContentConfig['collections'][C]['schema']`.
- `astro check` uses TypeScript `6.0.2` from the root `typescript` alias.
- Zod 4 schema inference through that generated Astro content type path
  collapses to `unknown` / `never` under TypeScript 6.
- Plain `tsc` TypeScript `7.0.2` accepted the same generated types.
- Probe on TypeScript `6.0.2` failed with:
  `src/probe.ts(6,23): error TS18046: 'a.data' is of type 'unknown'.`
- Direct `z.infer<typeof articleSchema>` worked under TypeScript `6.0.2`, so
  the schemas themselves are not the root cause.

Attempted fixes with no effect:

- Replace the generic `collection()` helper in `src/content.config.ts` with
  direct `defineCollection()` calls.
- Import `defineCollection` from `astro:content` instead of
  `astro/content/config`.
- Both experiments still produced 34 errors. Both were reverted.

Rejected fix:

- Point root `typescript` at `npm:typescript@7.0.2`.
- `astro check` then refused to run:
  `astro check does not currently support TypeScript 7.0. To continue using astro check, install TypeScript 6 instead.`
- `pnpm run lint` then failed:
  `Error: typescript-eslint does not support TS 7.0.`
- `package.json` and `pnpm-lock.yaml` were restored from backups. No net
  change remains from this experiment.

## Problem 2 — production build fails during prerender

Failing command output:

```
generating static routes
pageCount is not defined
  Location:
    .../astro/dist/core/render/route-cache.js:64:26
  Stack trace:
    at Module.getStaticPaths (.../dist/.prerender/chunks/_page__CebaYNRR.mjs:14:42)
```

Root cause:

- `src/pages/articles/page/[page].astro` defines `pageSize`, `ordered`, and
  `pageCount` in the frontmatter module body.
- `getStaticPaths()` references `pageCount`, `ordered`, and `pageSize`.
- Astro compiles `getStaticPaths()` into a separate prerender chunk. Those
  module-body constants are not in scope there.
- Required repair: compute `pageSize`, `ordered`, and `pageCount` inside
  `getStaticPaths()`; pass the needed values through `props` if the template
  needs them.

- Node local `v22.23.4` is older than latest active LTS `v26.13.1`.

  supported line.

- Tailwind packages disagree: `tailwindcss` `4.0.0` vs `@tailwindcss/vite`
  `4.3.5`; latest is `4.3.5` for both.

  `7.0.2` for `pnpm exec tsc`.
- `@astrojs/check` `0.9.12` does not support TypeScript `7.0`.

- Astro error message points to experimental TypeScript `7.1+` support via
  `@astrojs/ts-content-mapper`; installed TypeScript `7.0.2` is below that
  threshold.
