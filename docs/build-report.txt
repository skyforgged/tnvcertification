## Findings and fixes

### 1. TypeScript 7.0.2 did not check `.astro` templates

The prior setup ran `astro sync && tsc --noEmit`. That checked TypeScript files
only. Template expressions, component props, and content-data access inside
`.astro` files were not part of the TypeScript program.

Fix: moved to TypeScript `7.1.0-beta` and registered
`@astrojs/ts-content-mapper@0.2.0`. `check` and `typecheck` now pass
`--runExternalCode`. `tsc` parses `.astro` files through the mapper.

### 2. Content mapper configuration is strict

Putting `contentMappers` inside `compilerOptions` fails with:

`TS5023: Unknown compiler option 'contentMappers'`.

Omitting `jsx: "preserve"` produces `TS17004` errors in `.astro` files.

Fix: `contentMappers` is a root-level `tsconfig.json` field. `jsx` is
`"preserve"`, and `include` contains both `.astro/types.d.ts` and `src`.

### 3. `collection()` erased concrete Zod schema types

`src/content.config.ts` declared the helper parameter as `schema: z.ZodType`.
That widened every collection schema to an unknown output type. Once `.astro`
files were checked, `getCollection()` returned entries whose `data` was
`unknown`.

Verified failure: 36 `TS18046` errors across:

- `src/pages/[slug].astro`
- `src/pages/articles/[slug].astro`
- `src/pages/service/index.astro`
- `src/pages/services/[slug].astro`

Fix: changed the helper to
`function collection<T extends z.ZodTypeAny>(name: keyof typeof collectionRegistry, schema: T)`.
All 36 errors disappeared.

### 4. `pageSchema` omitted `draft`

After the schema helper fix, one error remained:

`TS2339: Property 'draft' does not exist` in `src/pages/[slug].astro`.

The route already filters `data.draft !== true`, and
`src/content/pages/0010-halaman-about-us.md` already contains `draft: false`.

Fix: `pageSchema` is now
`baseEntrySchema.extend({ draft: z.boolean().optional() })`. `npm run check`
exits `0` with no `error TS` lines.

### 5. Lint scope intentionally unchanged

`typescript-eslint` rejects TypeScript 7. Canary `8.73.1-alpha.7` is also
unsupported. Adding it would require a TypeScript 6 API alias, which the
toolchain policy prohibits.

Fix: no lint dependency or config changes. `eslint.config.js` still applies
JavaScript rules only. `npm run lint` exits `0`.
